### Core system rules (written into the top of COCO_TASKS.md; every card must keep them)
1. **Contract names are the fixed interface.** The physical layer underneath can be swapped (views → dynamic tables) without the semantic view, agent or app noticing.
2. **Clean data once, where it lands**, in a new `CONFORMED` schema of incremental dynamic tables (dedupe, standardize codes, convert currency, apply the edge-case rules). Never clean at query time. When source data changes, only the changed rows are refreshed.
3. **Masking lives only in the `GOVERNED` views** (the same names and columns as §7), keyed on `CURRENT_ROLE()`.
4. **One semantic view is the only definition of every metric.** App, procedures and agent all read it. No metric uses a masked column.
5. **Time is explicit.** One "as-of" date rule and one default window rule, identical for the app and the agent, so the same question can't get two numbers.
6. **Results are bounded.** Top-N and limit rules for the agent; the app handles NULL values and pages long lists.
7. **Paths are either deterministic or measured.** Metric and procedure paths are exact. The agent path is bounded by instructions, verified queries and a standing evaluation set with a recorded pass rate.
8. **Scale knobs only change speed and cost**: warehouse size, clustering, materialization, multi-cluster. B13 proves it.
9. **Cost controls**: auto-suspend, result cache, a resource monitor, query tags, and the app answers known KPIs without calling the LLM.
