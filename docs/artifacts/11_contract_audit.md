### 2.4 Abuse and cost

| Control | Limit |
|---|---|
| Ask limits (app, `config.ASK_LIMITS`) | 10 s between calls and 10 agent calls per visitor session; across all visitors, 3 at once, 30 per hour, 200 per day |
| Input size | 500 characters; more than 4 parts are not fanned out (`MAX_PARTS`) |

| Warehouse | `FORGE_WH` XS, 60 s auto-suspend; `FORGE_WH_MONITOR` 5 credits/day: notify 75%, suspend 100%, force 110% |
| Cortex | `OPS.FORGE_APP_CORTEX_BUDGET` 25 credits/month of the app user's Cortex use; at 100% it revokes the app role's USAGE on the agent ("Ask is paused"; the other screens keep working) |
| Alerting | `OPS.FORGE_OPS_WATCH` hourly (serverless): e-mails on data health not OK, failed agent questions, Ask paused, or warehouse ≥ 75%. The recipient comes from the user's profile, not the repo. A test e-mail was delivered (`NOTIFICATION_HISTORY` SUCCESS) |

### 2.5 Observability and audit

- **Agent traces** (automatic): `SNOWFLAKE.LOCAL.GET_AI_OBSERVABILITY_EVENTS`, summarised one row per question in `OPS.V_AGENT_REQUESTS` (question, answer, status, duration, tools, SQL query ids, tokens)
- **Failed app queries**: `OPS.V_APP_ERRORS`
- **Every app query is tagged** `forge_app:<function>:<anonymous visitor id>` (Claude Code, 1 Oct), so one visitor's questions and errors can be followed without any personal data
